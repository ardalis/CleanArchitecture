# Upgrading from template v12.0.x to v12.1

This guide is for solutions generated from `Ardalis.CleanArchitecture.Template` or `Ardalis.MinimalClean.Template` 12.0.x (both still target .NET 11). Version 12.1 moves the Aspire app host to **Aspire 17**, updates a few other packages, and fixes several [insecure defaults](#7-security-fixes).

You need this guide if you update the Aspire packages in a 12.0.x solution yourself: Aspire 17 marks `Aspire.AppHost.Sdk` and `AddProject<TProject>` as obsolete, and because the solution treats warnings as errors, the app host stops building:

```text
error CS0618: 'ProjectResourceBuilderExtensions.AddProject<TProject>(IDistributedApplicationBuilder, string)' is obsolete: 'Use AddDotnetProject(name, path) from the Aspire.Hosting.Dotnet package instead. ...'
warning ASPIRE012: ... uses the Aspire.AppHost.Sdk, which is obsolete but remains available for staged migration. ...
```

## Summary

| Area | v12.0.x | v12.1 | Action |
|---|---|---|---|
| Aspire CLI | Optional | **Required to run the app host** (F5, `dotnet run`, `aspire run`) | [Install it](#1-install-the-aspire-cli) |
| Aspire packages | 13.6.5 | 17.0.0 | [Required for Aspire 17](#2-update-package-versions) |
| App host project | `Aspire.AppHost.Sdk`, `ASPIRE010` `NoWarn` | `Microsoft.NET.Sdk` plus `Aspire.Hosting.AppHost` and `Aspire.Hosting.Dotnet` | [Required for Aspire 17](#3-update-the-app-host-project) |
| Starting the Web project | `AddProject<Projects.Your_ProjectName_Web>("web")` | `AddDotnetProject("web", "<path to .csproj>")` | [Required for Aspire 17](#4-use-adddotnetproject) |
| Other packages | Scalar 2, Serilog.AspNetCore 10 | Scalar 3, Serilog.AspNetCore 11 | [Optional](#5-other-package-updates) |
| `nuget.config` | Included a `c:\LocalNuget` source | nuget.org only | [Recommended](#6-nugetconfig) |
| Error responses | Exception message returned to clients outside Development | Generic message | [Recommended](#exception-messages) |
| Email sender | `Mailserver:Server` ignored; plain SMTP, no authentication | `Mailserver:Hostname`; STARTTLS required by default; optional credentials | [Recommended](#email-sender) |
| Startup migrations (Minimal) | Always ran; failures logged and ignored | Development or `DatabaseOptions:ApplyMigrationsOnStartup` only; failures stop startup | [Recommended](#startup-migrations-minimal-clean) |
| `UserSecretsId` | Same value in every generated solution | Unique per solution | [Recommended](#usersecretsid) |

## 1. Install the Aspire CLI

Aspire 17 app hosts are ordinary `Microsoft.NET.Sdk` projects. They no longer get the orchestrator (DCP) and the dashboard from NuGet packages; they use the ones bundled with the [Aspire CLI](https://learn.microsoft.com/dotnet/aspire/cli/overview). Install the CLI, at the same version as your Aspire packages, on every machine that runs the app host, including F5 in Visual Studio or Rider.

You still don't need the CLI to build the solution, run the Web project directly, or run the tests.

## 2. Update package versions

In `Directory.Packages.props`, move the Aspire packages to 17.0.0 and add the two new packages the app host needs:

```diff
-    <PackageVersion Include="Aspire.Hosting.SqlServer" Version="13.6.5" />
+    <PackageVersion Include="Aspire.Hosting.SqlServer" Version="17.0.0" />
+    <PackageVersion Include="Aspire.Hosting.AppHost" Version="17.0.0" />
+    <PackageVersion Include="Aspire.Hosting.Dotnet" Version="17.0.0" />
 ...
-    <PackageVersion Include="Aspire.Hosting.Testing" Version="13.6.5" />
+    <PackageVersion Include="Aspire.Hosting.Testing" Version="17.0.0" />
```

Keep every Aspire package on the same version. A leftover 13.x `Aspire.Hosting.Testing` is easy to miss because only the Aspire test project uses it.

## 3. Update the app host project

In `src/Your.ProjectName.AspireHost/Your.ProjectName.AspireHost.csproj`:

```diff
-<Project Sdk="Aspire.AppHost.Sdk/13.6.5">
+<Project Sdk="Microsoft.NET.Sdk">

   <PropertyGroup>
     <OutputType>Exe</OutputType>
-    <IsAspireHost>true</IsAspireHost>
     <UserSecretsId>...</UserSecretsId>
-    <!-- ASPIRE010: we intentionally use the DCP/Dashboard NuGet packages (AspireUseCliBundle=false) so F5 and dotnet run work without the Aspire CLI -->
-    <NoWarn>$(NoWarn);ASPIRE010</NoWarn>
   </PropertyGroup>

   <ItemGroup>
+    <PackageReference Include="Aspire.Hosting.AppHost" />
+    <PackageReference Include="Aspire.Hosting.Dotnet" />
     <PackageReference Include="Aspire.Hosting.SqlServer" />
     <PackageReference Include="MessagePack" />
   </ItemGroup>

   <ItemGroup>
-    <ProjectReference Include="..\Your.ProjectName.Web\Your.ProjectName.Web.csproj" />
-  </ItemGroup>
-  <ItemGroup>
-    <ProjectReference Include="..\Your.ProjectName.ServiceDefaults\Your.ProjectName.ServiceDefaults.csproj" IsAspireProjectResource="false" />
+    <ProjectReference Include="..\Your.ProjectName.ServiceDefaults\Your.ProjectName.ServiceDefaults.csproj" />
   </ItemGroup>

 </Project>
```

- **The Web `ProjectReference` is removed.** `AddDotnetProject` finds the project by its path (next step), so the app host no longer needs a reference to it. Under `Microsoft.NET.Sdk`, project references don't generate the `Projects.*` types anyway.
- **`IsAspireHost` and the `ASPIRE010` `NoWarn` are removed.** Neither is needed, and the build no longer raises `ASPIRE010`.
- **ServiceDefaults stays** as an ordinary project reference, so the `IsAspireProjectResource` attribute goes away.

## 4. Use AddDotnetProject

In `src/Your.ProjectName.AspireHost/AppHost.cs`:

```diff
-builder.AddProject<Projects.Your_ProjectName_Web>("web")
+// Path is resolved relative to the AppHost directory
+builder.AddDotnetProject("web", "../Your.ProjectName.Web/Your.ProjectName.Web.csproj")
   .WithReference(cleanArchDb)
```

The path is relative to the app host project's folder, not to the current working directory. The rest of the chain (`WithReference`, `WithEnvironment`, `WaitFor`) is unchanged.

If you added more projects to the app host, convert each `AddProject<Projects.X>` the same way and remove its `ProjectReference`. If something still needs the generated `Projects.*` types (for example `DistributedApplicationTestingBuilder.CreateAsync<Projects.Your_ProjectName_AspireHost>()` in a test project), see Microsoft's [migration guidance for ASPIRE012](https://aka.ms/aspire/diagnostics/aspire012). The template's tests don't use them.

## 5. Other package updates

These updates needed no code changes in the template:

- `Scalar.AspNetCore` 2.21.0 → **3.0.2**
- `Serilog.AspNetCore` 10.0.0 → **11.0.0**
- `Testcontainers` and `Testcontainers.MsSql` 4.16.0 → 4.17.0 (full template)
- `coverlet.collector` 10.1.0 → 10.1.1 (full template)

Scalar and Serilog are major versions. If your own code uses more of their APIs than the template does, check their release notes.

## 6. nuget.config

The 12.0.x `nuget.config` listed a `LocalNuget` source pointing at `c:\LocalNuget`, a folder on the template author's machine. Remove it:

```diff
     <add key="nuget.org" value="https://api.nuget.org/v3/index.json" />
-    <add key="LocalNuget" value="c:\LocalNuget" />
```

Package source mapping already sent every package to nuget.org, so 12.0.x solutions never restored anything from it, but the entry has no place in your repository. If you need a local package folder, add it to your user-level NuGet config instead.

## 7. Security fixes

These apply to both templates unless noted. None of them changes the API's successful responses.

### Exception messages

Outside Development, FastEndpoints' default exception handler returned the exception's message in the response, which can expose table, column and constraint names to anonymous callers. In `Configurations/MiddlewareConfig.cs`:

```diff
-      app.UseDefaultExceptionHandler(); // from FastEndpoints
+      app.UseDefaultExceptionHandler(useGenericReason: true);
```

The exception is still logged on the server.

### Email sender

Three changes to `MailserverConfiguration` and `MimeKitEmailSender`:

- **The host setting now works.** `appsettings.json` set `Mailserver:Server`, but the options class binds `Hostname`, so the sender always used `localhost`. Rename the key to `Hostname`.
- **STARTTLS is required by default.** `MailserverConfiguration` gains `SecureSocketOptions` (from `MailKit.Security`), defaulting to `StartTls`, and the sender passes it to `ConnectAsync` instead of `false` (which allowed falling back to cleartext). The local Papercut server doesn't support TLS, so `appsettings.Development.json` (and the full template's `appsettings.Testing.json`) set it to `None`:

  ```json
  "Mailserver": {
    "SecureSocketOptions": "None"
  }
  ```

- **Optional authentication.** `MailserverConfiguration` gains `Username` and `Password`. When `Username` is set, the sender calls `AuthenticateAsync` after connecting. Keep the password in user secrets or your host's secret store.

### Startup migrations (Minimal Clean)

The minimal template applied migrations and seed data on every startup in every environment, and logged and ignored a failed migration, so the app kept serving traffic against a half-migrated schema. It now matches the full template:

- Migrations and seeding run in Development, or when `DatabaseOptions:ApplyMigrationsOnStartup` is `true` (a new `DatabaseOptions` property, `false` in `appsettings.json`).
- A failed migration is logged and rethrown, so the app doesn't start. Seeding errors are still logged and ignored.

If you deploy by letting the app migrate itself, set `DatabaseOptions__ApplyMigrationsOnStartup=true` in that environment.

### UserSecretsId

The app host's `UserSecretsId` wasn't replaced when generating a solution, so every solution generated from the template on a machine shared one user-secrets store, including the SQL Server password Aspire generates. New solutions now get their own. To fix an existing solution, replace the `UserSecretsId` in your app host's csproj with a new GUID (or run `dotnet user-secrets init` after removing it), then set any secrets you need again.

## Minimal Clean template

`Ardalis.MinimalClean.Template` 12.1 gets the same changes, with two differences:

- Its app host already referenced `Aspire.Hosting.AppHost`. In `MinimalClean/Directory.Packages.props` (your solution's `Directory.Packages.props`), move `Aspire.Hosting.AppHost` and `Aspire.Hosting.SqlServer` to 17.0.0 and add `Aspire.Hosting.Dotnet` 17.0.0. It has no `Aspire.Hosting.Testing` or Testcontainers.
- Its csproj used `<Project Sdk="Microsoft.NET.Sdk">` with a nested `<Sdk Name="Aspire.AppHost.Sdk" Version="13.6.5" />`. Remove the nested `Sdk` element instead of changing the `Project` attribute, then make the other csproj changes from [step 3](#3-update-the-app-host-project).

In `AppHost.cs`:

```diff
-builder.AddProject<Projects.Your_ProjectName_Web>("web")
+builder.AddDotnetProject("web", "../Your.ProjectName.Web/Your.ProjectName.Web.csproj")
```
