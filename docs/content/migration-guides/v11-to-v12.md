# Upgrading from v11.x to v12.x

This guide covers moving a project started from version `11.x` of `Ardalis.CleanArchitecture.Template` (or `1.x` of `Ardalis.MinimalClean.Template`) to version `12.0.0`.

## Version numbers

Starting with `12.0.0`, both templates share one version number and ship together:

| Package | Previous version | New version |
| --- | --- | --- |
| `Ardalis.CleanArchitecture.Template` | `11.1.1` | `12.0.0` |
| `Ardalis.MinimalClean.Template` | `1.1.1` | `12.0.0` |

MinimalClean jumps from `1.1.1` to `12.0.0`. The jump only aligns the version numbers. MinimalClean didn't change any more than the full template did.

## The "Diff" Strategy

As with earlier versions, there is no automated upgrade. The most reliable approach is:

1. Install the new template: `dotnet new install Ardalis.CleanArchitecture.Template` (or `Ardalis.MinimalClean.Template`).
2. Generate a **brand new solution** with the same project name you used originally.
3. Diff it against a solution generated from the version you started with (or against your current codebase), and apply the changes you want.

## Key Changes in v12.x

### 1. .NET 11

All solutions now target `net11.0`, and `global.json` requires the .NET 11 SDK (`11.0.100` or later).

- **Action Required**: Install the .NET 11 SDK, update `TargetFramework` in `Directory.Build.props`, and update `global.json`.

### 2. Package upgrades

Every package is on its latest stable version. The upgrades most likely to need code changes are:

- **FastEndpoints 7.x → 9.0.0**: Review your endpoints against the template's `Web` project and the [FastEndpoints release notes](https://fast-endpoints.com/).
- **xUnit 2.x → xUnit v3** (full template): Test projects now reference `xunit.v3.mtp-off`. Compare your test `.csproj` files and `Directory.Packages.props` with the new template.

- **Action Required**: Compare `Directory.Packages.props` and update your Central Package Management versions.

### 3. `Get` use case renamed to `GetById` (full template)

The Contributor query now matches the `GetById` endpoint that calls it:

| v11 | v12 |
| --- | --- |
| `UseCases/Contributors/Get/` | `UseCases/Contributors/GetById/` |
| `GetContributorQuery` | `GetContributorByIdQuery` |
| `GetContributorHandler` | `GetContributorByIdHandler` |

- **Action Required**: None. Your code keeps working as it is. If you have used the old names as a pattern for your own use cases, you may want to rename those too.

### 4. Bug fixes worth copying (full template)

- **`ContributorId` and EF Core temporary keys**: EF Core gives new entities a temporary negative key until `SaveChanges`. In v11, converting that key back to the `ContributorId` value object failed validation, so inserts failed. The value object now uses `[ValueObject<int>(deserializationStrictness: DeserializationStrictness.AllowAnything)]`. `ContributorId.From()` still validates. Apply the same change to any strongly-typed ID value objects you created from this pattern.
- **`UseDbGeneratedIds` migration on SQL Server**: The `sp_rename` calls in this migration used bracketed names, which made it fail on SQL Server. If you haven't applied this migration to a SQL Server database yet, copy the corrected version.

### 5. Testing improvements (full template)

- Functional tests fall back to SQLite when Docker is unavailable or can't run Linux containers, and run against SQL Server Testcontainers when it can.
- All test assertions use [Shouldly](https://docs.shouldly.org/).

### 6. Dependency rules (MinimalClean)

MinimalClean now enforces boundaries between feature slices at build time with [NsDepCop](https://github.com/realvizu/NsDepCop), using the rules in `src/MinimalClean.Architecture.Web/config.nsdepcop`. A violation fails the build.

- **Action Required**: If you adopt the rules, expect build errors wherever your slices reference each other directly. See [Enforcing Dependency Rules](../../dependency-rules/) for the rule syntax and how to add rules for new slices.

### 7. Template packaging fixes

Project names that aren't valid C# namespaces (for example, names containing hyphens) now produce correctly renamed files and folders. This affects only new projects.

The `Ardalis.CleanArchitecture.Template` package also no longer contains a copy of MinimalClean. In v11, every `clean-arch` solution included a `MinimalClean` folder you could safely delete, and installing the package registered `min-clean` as well. Install `Ardalis.MinimalClean.Template` to get `min-clean`.

New solutions also leave out files that only belong in the template's repository: `CODE_OF_CONDUCT.md`, `CONTRIBUTING.md`, `icon.png`, `.claude/`, `PARALLEL_TEST_EXECUTION.md`, and `TESTCONTAINERS_IMPLEMENTATION.md`. You can delete these from existing solutions. New `clean-arch` solutions now also get a `.gitignore`. If yours doesn't have one, copy it from a newly generated solution, or run `dotnet new gitignore`. The useful parts of the two testing notes, updated for v12, are now on the [Testing](../../testing/) page.
